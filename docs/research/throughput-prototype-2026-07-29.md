# 高吞吐原型验证记录

日期：2026-07-29

## 验证问题

验证单写SQLite worker、500条或100毫秒批次、增量投影、最近500条弹幕和节流IPC能否满足以下目标：

- 每秒200条直播事件。
- 单场100万条事件。
- 连续12小时运行时内存与队列有明确上限。

原型位置：[高吞吐与实时聚合原型](../prototypes/throughput/README.md)。

## 环境

- 架构：`arm64`
- 系统：macOS 26.5.1，Build 25F80
- Node：24.14.1
- SQLite：Node内置`node:sqlite`，系统SQLite为3.51.0
- 数据：固定规则生成的脱敏合成事件

本次没有读取线上消息、用户ID、Cookie或临时凭据。

## 原型内容

- 主线程生成事件并维护有界接收队列。
- SQLite同步写入在Node worker中执行。
- 事实表包含弹幕、礼物、醒目留言和热度。
- 同一事务更新会话摘要、活跃用户、10秒桶和高频词快照。
- 弹幕同时进入FTS5三元组索引。
- 主线程只维护固定容量实时投影并构造renderer载荷。

## 第一次100万条结果

第一次运行写入和所有计数通过，但3字符FTS搜索没有达到门槛：

- 写入约26,730条/秒。
- writer提交P99约58毫秒。
- 3字符FTS热查询约2.1秒。

查询计划直接关联FTS虚拟表与事实表。Node内置SQLite驱动在该查询形态上耗时随整场行数增长，即使FTS本身只返回少量匹配。

修正为先通过`MATERIALIZED`子查询取得FTS匹配`rowid`，再关联事实表和排序。同一个2万条数据库上，查询从约115毫秒降至1毫秒以内。

这个失败被保留为实现约束：正式查询必须固定SQL形态，并为查询计划增加回归检查。

## 12小时门槛

原型已经提供`soak`档位：

```bash
node --disable-warning=ExperimentalWarning docs/prototypes/throughput/benchmark.mjs --profile soak
```

负载平时为20条/秒，每15分钟加入1分钟200条/秒，12小时共1,382,400条。

本次规划阶段没有把短时原型运行冒充12小时验证。正式实现完成后，必须用打包应用、最终SQLite驱动和生产worker运行完整12小时，并按[高吞吐与实时聚合规格](../spec/throughput-and-realtime-aggregation.md)保存脱敏结果。

## 已确定调整

- 高频词使用128项Space-Saving近似候选，避免词典随整场增长。
- `session_keywords`保存估算值和误差上界。
- 1至2字符搜索使用会话内参数化子串扫描。
- 3字符以上搜索使用FTS5三元组索引和物化匹配ID。
- 会话摘要保存首条与末条弹幕事实ID，为FTS查询限定当前会话范围。
- renderer推送保留最新200条，主进程最近弹幕固定500条。
- 12小时内存斜率从前30分钟预热结束后开始计算。

## 局限

- `node:sqlite`不是最终生产驱动。
- 原型没有启动Electron和React，只模拟主线程、writer worker和renderer载荷。
- 新连接查询仍可能命中macOS文件缓存，不能视为重启后的冷缓存。
- 本次只运行了120秒定速测试，12小时门槛仍需正式实现后执行。

# B站网页直播弹幕协议契约

验证日期：2026-07-29

## 结论

匿名采集任意公开B站直播间的实时弹幕在当前协议条件下可行。实测已经完成房间号规范化、WBI签名、弹幕节点发现、匿名WebSocket鉴权、心跳回复、Brotli解压和多包递归解析。

这套能力来自B站网页直播间正在使用的内部接口，不属于面向第三方承诺稳定性的公开产品接口。第一版可以采用，但必须隔离在可替换的协议适配器中，并用脱敏固定样本约束行为。任何HTTP返回、WebSocket数据和命令字段都不能直接进入数据库或渲染进程。

## 验证范围与证据等级

### 已实测

- 短房间号可通过`room_init`转换为真实房间号。
- 未签名调用`getDanmuInfo`返回`-352`，加入当前WBI签名后返回`code=0`、临时令牌和6个WebSocket节点。
- 匿名调用`nav`虽然返回未登录状态码，响应中仍包含可用的WBI图键。
- 匿名指纹接口返回可用的`b_3`。WebSocket鉴权在`uid=0`且`buvid`为空时也成功，因此指纹获取失败不必退回Cookie。
- 使用`protover=3`鉴权成功，收到鉴权回复和热度心跳回复。
- 20秒活跃房间样本中出现版本`0`、`1`和`3`的数据包，版本`3`使用Brotli，解压后包含多个完整内层包。
- 当前网页播放器源码使用WBI调用`getDanmuInfo`，连接`host_list`中的WSS节点，鉴权参数包含`platform=web`、`type=2`、临时令牌，并使用`protover=3`。

### 交叉核对

- B站开放平台长链文档确认16字节大端包头、操作码、心跳和压缩包递归解析方式。开放平台的鉴权来源不同，只用于核对传输层，不能替代网页协议实测。
- 第三方项目`champkeh/blive-ws`的包头、节点轮换、鉴权字段和版本`2`、`3`解压逻辑与实测一致。该项目当前源码含嵌入式凭证类配置，因此不作为依赖，也不复制其配置或业务代码。

## 协议适配器版本

第一版适配器版本固定为`bilibili-web-v1`。

- 对额外JSON字段保持宽容，忽略未知字段。
- 对房间号、节点列表、临时令牌、包头长度和业务命令等必需字段严格校验。
- 每个会话记录适配器版本，不记录临时令牌、WBI键或原始响应。
- 协议升级必须新增适配器版本和脱敏样本，不能直接改变旧样本含义。
- 未知命令只记录命令名与计数。命令名先按第一个冒号截断，例如把`DANMU_MSG:4:0:2`归一为`DANMU_MSG`。

## 端到端连接契约

### 1. 解析用户输入

接受纯数字房间号或`live.bilibili.com`直播链接。只提取十进制数字，拒绝空值、负数、超长数字和非B站直播链接。

调用：

```text
GET https://api.live.bilibili.com/room/v1/Room/room_init?id={inputRoomId}
```

必需响应：

- `code`为`0`。
- `data.room_id`为正整数，作为后续唯一真实房间号。
- `data.live_status`为已知整数。

已知直播状态：

- `0`：未开播。
- `1`：直播中。
- `2`：轮播或特殊播放状态。

后续发现和鉴权始终使用真实房间号，不能继续使用短号。

### 2. 获取WBI图键

调用：

```text
GET https://api.bilibili.com/x/web-interface/nav
```

匿名请求可能返回未登录状态码，但只要`data.wbi_img.img_url`和`data.wbi_img.sub_url`存在且格式有效，就可以生成签名。不能仅因为顶层状态码非零而丢弃有效图键。

从两个URL的文件名取出图键和子图键，按以下索引表混排并截取前32个字符：

```text
46,47,18,2,53,8,23,32,15,50,10,31,58,3,45,35,
27,43,5,49,33,9,42,19,29,28,14,39,12,38,41,13,
37,48,7,16,24,55,40,61,26,17,0,1,60,51,30,4,
22,25,54,21,56,59,6,63,57,62,11,36,20,34,44,52
```

WBI签名输入：

- `id={realRoomId}`
- `type=0`
- `web_location=444.7`
- `wts={当前Unix秒}`

签名步骤：

1. 删除每个参数值中的`!'()*`字符。
2. 按参数名排序。
3. 使用标准URL编码生成查询字符串。
4. 计算`MD5(查询字符串 + 32字符混排键)`，结果写入`w_rid`。

网页页面中的`spm_prefix`是`web_location`的来源。2026-08-12页面值为`444.7`，已据此更新实现与固定测试。实现应优先使用适配器内已验证值；协议升级时重新核对网页值。

WBI键只保存在内存中。应用启动、签名失败或完整节点轮换失败时重新获取。

### 3. 获取匿名设备标识

调用：

```text
GET https://api.bilibili.com/x/frontend/finger/spi
```

若`data.b_3`存在，将它作为本次进程内的`buvid`使用。不得把它写入数据库、日志或固定测试样本。

若接口失败，允许使用空字符串继续鉴权。当前匿名实测在空`buvid`下鉴权成功。第一版不得读取浏览器Cookie，也不得要求用户提供Cookie。

### 4. 获取弹幕节点与临时令牌

调用：

```text
GET https://api.live.bilibili.com/xlive/web-room/v1/index/getDanmuInfo
```

请求使用上一节的WBI参数和签名。建议请求头：

```text
Accept: application/json
Origin: https://live.bilibili.com
Referer: https://live.bilibili.com/{realRoomId}
User-Agent: 当前Electron使用的稳定桌面UA
```

不得发送Cookie。

必需响应：

- `code`为`0`。
- `data.token`为非空字符串。
- `data.host_list`为非空数组。
- 每个候选节点至少包含合法的`host`和`wss_port`。

临时令牌只能存放在采集器内存中。日志、IPC、数据库、崩溃报告和测试快照都必须在边界处删除该字段。

### 5. 建立WebSocket连接

依次连接：

```text
wss://{host}:{wss_port}/sub
```

只有已经取得有效临时令牌时，才允许把`wss://broadcastlv.chat.bilibili.com:443/sub`作为最后一个主机候选。节点列表与候选顺序只属于当前引导周期。

每次只保留一个活动连接，避免重连交叠造成重复事件。单个节点打开失败或异常关闭后轮换到下一个节点。所有节点都失败后，重新执行WBI、指纹和`getDanmuInfo`流程。

### 6. 发送鉴权包

所有整数使用大端序。固定包头为16字节：

| 偏移 | 长度 | 含义 |
| --- | ---: | --- |
| `0` | 4 | 完整包长 |
| `4` | 2 | 包头长，固定为`16` |
| `6` | 2 | 协议版本 |
| `8` | 4 | 操作码 |
| `12` | 4 | 序号 |

鉴权包使用：

- 包头版本`1`
- 操作码`7`
- 序号`1`
- UTF-8 JSON正文

正文契约：

```json
{
  "uid": 0,
  "roomid": 123,
  "protover": 3,
  "buvid": "",
  "platform": "web",
  "type": 2,
  "key": "<临时令牌>"
}
```

示例中的房间号和令牌是固定占位符。测试不能写入线上返回值。

操作码`8`为鉴权回复。正文`code=0`才算成功；非零、超时、格式错误或连接在回复前关闭，都视为鉴权失败，并触发完整引导刷新。

当前网页还会发送`support_ack`和场景字段。这些字段不是匿名鉴权成功的必要条件，第一版不纳入必需契约。

### 7. 心跳

鉴权成功后立即发送一次心跳，此后每30秒发送操作码`2`的空正文包。

操作码`3`是心跳回复。正文前4字节为无符号大端热度值。解析时仍要遵守包头声明的完整包长，不能假定一个WebSocket消息只含一个回复包。

连续两个心跳周期没有收到任何有效服务端数据时，将连接标记为失活并轮换节点。精确的用户可见状态和会话缺口规则由采集状态机任务确定。

### 8. 解析业务包

操作码`5`为业务消息。解析器必须循环读取一个WebSocket消息中的全部包：

- 版本`0`、`1`：正文按UTF-8 JSON解析。
- 版本`2`：正文使用zlib解压，解压结果作为完整包序列递归解析。
- 版本`3`：正文使用Brotli解压，解压结果作为完整包序列递归解析。

第一版支持的业务命令：

- `DANMU_MSG`
- `SEND_GIFT`
- `SUPER_CHAT_MESSAGE`
- `LIVE`
- `PREPARING`

连接状态和热度分别来自采集状态机与操作码`3`，不伪装成B站业务事件。业务字段映射由事件模型任务确定。

建议安全上限：

- 单个网络帧不超过16MiB。
- 单次解压结果不超过64MiB。
- 递归深度不超过4层。
- 单帧最多解析10000个内层包。

超过上限、包长小于包头、包长越界、包头长度异常、解压失败或JSON格式错误时，丢弃当前异常单元并增加脱敏错误计数。短时间连续出现同类错误时关闭连接并重新引导，不能把原始正文写入日志。

## 失败边界

| 阶段 | 识别条件 | 适配器动作 | 可记录内容 |
| --- | --- | --- | --- |
| 输入 | 无有效房间号 | 立即拒绝 | 本地错误码 |
| 房间发现 | HTTP失败、超时 | 有上限地退避重试 | 阶段、HTTP状态 |
| 房间发现 | 顶层状态码非零或缺少真实房间号 | 停止本次启动 | B站状态码 |
| 等待开播 | `live_status=0` | 进入轮询，不创建历史会话 | 房间状态 |
| 特殊状态 | `live_status=2` | 保留状态，不当作正常开播 | 房间状态 |
| WBI | 缺少图键或URL格式异常 | 刷新一次，仍失败则停止 | 阶段、字段名 |
| 节点发现 | `code=-352` | 退避后刷新WBI再试 | 状态码、尝试次数 |
| 节点发现 | 其他非零状态码 | 按上游拒绝处理 | 状态码 |
| 节点发现 | 令牌或节点列表缺失 | 按协议不兼容处理 | 缺失字段名 |
| WSS连接 | TLS、DNS、打开超时 | 轮换节点 | 节点序号、错误类别 |
| 鉴权 | 非零、超时、提前关闭 | 丢弃令牌并完整刷新 | 鉴权状态码 |
| 活跃连接 | 心跳失活或网络关闭 | 记录缺口起点并重连 | 时间、关闭码 |
| 解码 | 长度、解压或JSON错误 | 丢弃异常单元，达到阈值后重连 | 错误类别、计数 |
| 命令 | 未知`cmd` | 忽略业务内容 | 归一后的命令名、计数 |
| 停播 | `PREPARING`或房间状态转为未开播 | 交给状态机正常结束 | 归一命令、时间 |

退避时间应加入随机抖动并设置上限。单次节点列表只尝试一轮，之后必须重新获取临时令牌。应用不得通过加入Cookie绕过`-352`或其他风控。

## 可重复测试样本

所有样本必须人工构造或从实测结构中彻底改写，不能保存线上完整消息。推荐目录：

```text
test/fixtures/bilibili-web-v1/
```

必须覆盖：

1. 固定假图键和固定`wts`的WBI签名向量。
2. 短号转真实号、未开播、轮播、无效房间和字段缺失的HTTP响应。
3. `getDanmuInfo`成功、`-352`、非零状态码、空令牌和空节点列表。
4. 操作码`8`鉴权成功、失败与格式错误。
5. 操作码`3`热度回复。
6. 版本`0`和`1`的单业务包。
7. 同一帧包含多个完整包。
8. 版本`2`的zlib嵌套包。
9. 版本`3`的Brotli嵌套包。
10. 带冒号后缀的`DANMU_MSG`命令。
11. 未知命令。
12. 包长过小、包长越界、异常包头、截断压缩数据、超深递归和超大解压结果。

测试样本中的用户标识、房间号、昵称、文本、金额、消息标识、图键、指纹和令牌全部使用显然虚构的值。

## 实施约束

- 协议适配器只在Electron主进程中运行。
- HTTP响应与WebSocket正文经过运行时校验后，才能转换为内部事件。
- 临时令牌、WBI键、指纹、原始用户ID和完整原始消息不能进入日志、IPC、数据库或Git。
- 诊断日志只保留阶段、内部错误码、上游状态码、节点序号、重试次数、关闭码、耗时和计数。
- 内部事件优先使用平台消息标识去重。缺少消息标识时不能假装能够严格去重，状态机应避免重叠连接并记录重连缺口。
- 网页协议没有稳定性承诺。对外分发、商业化或需要主播授权的场景，应重新评估B站直播开放平台。

# 抖音第一版事件范围与不可用语义

版本：`douyin-web-v1`

日期：2026-08-01

## 第一版保存与展示

- 普通弹幕：保存并在实时弹幕中展示接收时间、展示昵称和正文。正文与昵称进入内部模型前分别限制长度，原始用户ID不得进入IPC、日志或数据库。
- 直播与连接状态：保存采集开始、停止、连接恢复和数据缺口；等待开播与下播需在线验证后才进入正式状态机。
- 弹幕看板：展示弹幕总数、最近一分钟速率、活跃发言人数、采集时长和最后消息时间。

## 仅作为协议诊断，不进入第一版业务数据

- 点赞、进场和关注消息已能匿名收到，但不持久化、不进入看板指标，也不计入活跃用户。
- 未识别消息方法只计入脱敏诊断摘要，不向renderer暴露方法名或原始载荷。

## 事件不可用

以下项目在匿名网页协议得到稳定证据前显示为不可用，不能显示为数值零：

- 礼物数量与价值。
- 醒目留言数量与价值。
- 当前在线人数、累计观看人数和平台热度。
- 下播事件和断线后的补发完整性。

实时页使用不可用标签并说明匿名协议暂未提供可靠数据。历史摘要使用`null`表达不可用，禁止写入`0`。数据缺口与事件不可用是两种状态：前者表示本应可用但某个时间段无法确认完整性，后者表示该平台能力本身没有可靠证据。

## 可使用看板验收

1. 用户选择抖音并输入纯数字`web_rid`或`https://live.douyin.com/<web_rid>`链接后，可以开始匿名采集。
2. 首次WSS业务帧解码成功后状态变为正在采集；停止后不再接收新消息。
3. 实时页最多保留500条普通弹幕，展示时间、昵称和正文，不展示平台原始用户ID。
4. 看板持续更新弹幕总数、最近一分钟速率、活跃发言人数、采集时长和最后消息时间。
5. 礼物、醒目留言与未经验证的平台数值显示为不可用，不显示为零。
6. 关闭主窗口只隐藏窗口，采集继续；重新显示窗口后恢复当前快照。
7. 启动、停止和订阅只能通过preload白名单接口，renderer不能访问Node、Electron、网络原始帧或任意IPC通道。

## 当前交付边界

达到上述验收表示抖音实时看板可使用，不等于第一版完整发布。SQLite历史、等待开播、自动重连、断线缺口、礼物能力和正式产物长稳验证仍按后续任务推进，界面必须如实标注未完成能力。

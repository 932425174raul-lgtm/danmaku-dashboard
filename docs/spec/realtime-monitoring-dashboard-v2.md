# 实时趋势监控看板规格

版本：`v2`

日期：2026-08-12

## 目标

实时看板需要让直播运营者在直播过程中看清三个问题：

1. 当前一段互动是在升温、平稳还是回落。
2. 弹幕、活跃发言人数、热度、礼物和醒目留言分别如何变化。
3. 连接中断是否造成数据缺口，当前趋势是否仍可用于判断。

界面继续使用棱镜编辑风。颜色用于区分指标和状态，图表不使用霓虹外发光、网格背景或HUD装饰。

## 指标边界

- 弹幕量：本机已经成功写入数据库的普通弹幕数量。
- 活跃发言人数：按本机匿名标识估算的去重发言人数，不是在线观众人数。
- 直播热度：平台公开协议返回的热度值，不解释为观看人数。
- 礼物：已经成功写入数据库的礼物数量。
- 醒目留言：已经成功写入数据库的醒目留言数量。
- 数据缺口：采集连接中断的区间。缺口期间没有可靠数据，不能按零互动解释。
- 抖音匿名协议没有稳定提供的热度、礼物和醒目留言继续显示为不可用，不绘制零值趋势。

## 时间窗

- 原始实时趋势继续使用10秒统计桶，最多保留最近180个桶，对应30分钟。
- 图表在界面中按1分钟合并，最多显示30个点，减少窄栏中的视觉噪声。
- 弹幕、礼物和醒目留言按分钟求和。
- 热度按分钟取峰值。
- 活跃发言人数图显示该分钟内10秒桶的短时峰值，并明确标注为估算值。
- 当前一段状态使用最多5分钟的滚动窗口，与前一段等长窗口比较。
- 会话不足2分钟时不下趋势结论，显示正在积累。

## 当前一段状态

状态只根据弹幕量变化判断，避免把不同量纲拼成无依据的综合分数：

- `starting`：可比较数据不足2分钟。
- `warming`：当前段弹幕比前一段增加至少25%，且绝对变化超过3条。
- `steady`：变化没有达到升温或回落门槛。
- `cooling`：当前段弹幕比前一段减少至少25%，且绝对变化超过3条。
- `quiet`：当前段没有弹幕。
- `gap`：当前段或对比段存在数据缺口，不给出升温、平稳或回落判断。

状态区同时显示当前段的弹幕、活跃发言人数、热度、礼物和醒目留言，以及相对前一段的变化。前一段为零时显示新增，不显示无穷百分比。

## 页面结构

实时看板从上到下排列：

1. 当前一段状态与五项对比数字。
2. 有缺口时显示连接中断提示。
3. 最近30分钟趋势监控，包括弹幕量、活跃发言、直播热度、礼物和醒目留言五张图。
4. 六项整场总览指标。
5. 高频词与活跃用户排行。
6. 会话状态和数据能力说明。

五张趋势图各使用一种固定颜色，并同时使用标题、单位和数值区分，不能只靠颜色辨认。数据缺口使用珊瑚红虚线区间，并在图例中解释。

## 固定容量与性能

- 主进程仍只保留180个10秒桶。
- 每个桶的活跃发言人数使用固定大小的基数估算器，不保存用户集合。
- 实时IPC包仍不得超过256KiB，超限时优先裁剪最近弹幕，不裁剪监控指标。
- 界面只渲染最多30个分钟点乘5张图，不按整场时长增加DOM节点。

## 验收标准

- AC-1：实时快照为每个10秒桶提供弹幕量、活跃发言人数估算、礼物、醒目留言、热度峰值和缺口标记。
- AC-2：当前一段状态能区分正在积累、升温、平稳、回落、安静和数据缺口，并附带等长时间段对比数字。
- AC-3：实时页显示五张最近30分钟趋势图，颜色、标题、单位和不可用状态清楚。
- AC-4：趋势图按1分钟合并，最多渲染30个点，缺口不能被画成正常零值。
- AC-5：活跃发言人数和直播热度的边界文案清楚，不将其写成在线人数。
- AC-6：抖音不可用指标不显示零值趋势。
- AC-7：实时快照保持固定内存，经过IPC限制后不超过256KiB。
- AC-8：760px以下的看板仍无横向滚动，图表文字与交互目标保持可读。

# 直播结束复盘规格

> 版本：2.0，2026-08-12。本文是直播结束分析页的单一权威。

## 目标

直播结束后，历史详情页根据本机已经保存的事实数据生成可追溯的观众反馈复盘，帮助用户确定值得回看的时段和下一场可以验证的调整方向。

## 数据边界

- 复盘只分析弹幕、礼物、醒目留言、平台热度和数据缺口，不读取直播音频、画面或主播逐字稿。
- 分时人数指该时间桶内去重的活跃发言人数，不等于在线观众人数。
- 平台热度不能解释为在线人数。
- 建议只描述数据关联和回看方向，不能把峰值直接归因为某个主播行为。
- 全部聚合在SQLite只读Worker中完成，不上传弹幕，不调用外部AI服务。

## 验收标准

### AC-1整场摘要

结束场次展示弹幕总数、活跃发言人数、平均每位发言者弹幕数、数据缺口和数据覆盖提示。活动场次不生成最终复盘。

### AC-2重复弹幕

按清理后已经入库的完整弹幕正文精确分组，展示次数最多的前五条、出现次数、发言人数和首次至末次出现时间。只出现一次的正文不进入排行。

### AC-3分时趋势

按自适应时间桶返回弹幕数、去重活跃发言人数、礼物数、醒目留言数、热度峰值和缺口标记。12小时以内使用5分钟时间桶，超过12小时后把总桶数限制在144个以内。

### AC-4峰值与建议

展示弹幕峰值时段、活跃发言人数峰值时段、前三弹幕时段占比和最多重复弹幕，并生成可以回溯到这些数字的回看建议。不得生成没有数据依据的情绪、话题或因果结论。

### AC-5数据缺口

任何时间桶与数据缺口相交时标记为缺口；存在缺口时，复盘页提示趋势和排行可能低估真实互动。

### AC-6响应式与可访问性

宽窗口按摘要、趋势、反馈和建议排列；760px以下保持单列，不产生横向溢出。趋势图同时使用颜色、图例和文字摘要，不能只依赖颜色。

### AC-7整场结论

复盘页在首屏给出一段整场结论，明确写出弹幕高峰时段、该时段弹幕量和活跃发言人数。结论不读取直播内容，不生成情绪、话题或因果判断。没有弹幕时明确说明数据不足。

### AC-8高峰时段排名与多指标趋势

- 按弹幕量从高到低展示前5个时间格，并显示弹幕数、活跃发言人数、全场占比和数据缺口。数量相同时，先按活跃发言人数降序，再按时间升序。
- 分时趋势同时展示弹幕量、活跃发言人数、平台热度峰值、礼物和醒目留言。平台匿名协议不提供的指标显示为不可用，不按零值解释。

### AC-9趋势判断与下场验证清单

- 活跃发言趋势只使用没有数据缺口的时间格。至少有4个可靠时间格时，比较前后两半的平均活跃发言人数。变化幅度至少20%且绝对差至少2人时，判断为上升或回落，否则判断为平稳。数据不足时不强行判断。
- 调整清单至少覆盖弹幕高峰回看、重复弹幕语境确认和活跃发言趋势。每条都分成「数据依据」和「下场验证」，不直接宣称某个主播行为造成了数据变化。

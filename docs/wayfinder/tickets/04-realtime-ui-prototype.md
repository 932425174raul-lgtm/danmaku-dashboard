## Question

单窗口应用如何同时呈现实时弹幕、实时看板、房间身份、采集状态、数据缺口和主要操作；窄窗口、空状态、等待开播、断线、风控、历史查询和菜单栏后台状态需要怎样的可交互原型，才能在编码前验证信息层级和操作路径？

## Resolution

采用方案A的左右并列布局，并吸收另外两个方案的局部优点：

- 宽窗口左侧实时弹幕、右侧实时看板，顶栏统一显示房间、状态、主导航和菜单栏入口。
- 弹幕列表借鉴方案B的字号和行距，长时间观看时仍能快速扫描。
- 趋势图借鉴方案C的数据缺口带状标记，缺失区间不按零事件绘制。
- 小于`760px`时使用弹幕与看板页签；历史页先显示列表，选择会话后进入详情。
- 状态横幅覆盖等待开播、连接恢复、匿名访问受限、存储故障和启动失败。
- 历史详情包含摘要、缺口、会话内搜索和删除整场确认。
- 菜单栏显示当前房间、采集状态、最后消息或重试时间，并提供显示窗口、停止和退出。

可交互原型见[实时监控界面原型](../../prototypes/realtime-monitor/README.md)，正式界面契约见[实时监控界面规格](../../spec/realtime-ui.md)。

原型已在`1440px`和`390px`宽度验证3种方案、5种采集场景、键盘方案切换、窄窗口页签、历史列表与详情返回以及删除确认。页面没有横向溢出或脚本错误。

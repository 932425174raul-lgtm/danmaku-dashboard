# 增加抖音直播采集能力

## Destination

在现有`弹幕看板.app`中增加抖音公开直播间采集能力。用户选择平台并输入房间号或直播链接后，应用能在不读取账号Cookie的前提下后台接收、规范化并保存抖音实时事件，同时复用现有实时弹幕、看板、历史记录、数据缺口和Apple Silicon安装包能力。

## Notes

- 已确认的桌面生命周期、单活动会话、本地SQLite、历史删除、数据缺口、性能目标和Apple Silicon交付边界继续以[项目词汇表](../../../CONTEXT.md)与[B站第一版实施规格](../../spec/implementation-plan.md)为准。
- 抖音只新增平台适配器和平台相关展示语义，不复制Electron生命周期、数据库worker、实时投影或打包基础设施。
- 第一版继续禁止读取、保存或要求用户提供抖音账号Cookie。匿名网页协议无法稳定提供的数据必须明确显示为不可用，不能按零值处理。
- 官方直播玩法能力与任意公开直播间匿名采集是两种接入方式，不能混为同一条协议路径。
- 本地图包含实施任务；每个任务都要先固定可验证接口，再写脱敏测试与实现。

## Decisions so far

<!-- 每个已关闭任务在这里保留一行结论索引。 -->

- [协议边界](tickets/01-douyin-protocol-contract.md)：匿名页面WSS、gzip、业务消息、ACK和心跳已在线实测；正式适配器仍需独立签名与固定消息体样本。
- [事件范围与缺失语义](tickets/02-douyin-event-scope.md)：第一版保存普通弹幕和会话状态；匿名未证实的礼物、醒目留言、人数与热度显示为不可用，不能按零处理。

## Not yet specified

- 礼物、下播与跨房间稳定性仍未确定。
- 动态签名与Protobuf结构怎样版本化，才能在协议变化后解释失败并保留旧样本含义。
- 抖音在线人数、累计观看、点赞与B站热度的看板文案和空值语义。
- 抖音风控、协议拒绝与普通网络故障怎样映射到现有启动失败和数据缺口。

## Out of scope

- 读取浏览器登录态、导入抖音Cookie或保存任何会话凭证。
- 绕过验证码、设备校验、账号限制或平台访问控制。
- 第一版接入抖音直播玩法开放平台、抖音云或主播授权流程。
- 下载、录制或转码直播音视频。
- 同时采集多个平台或多个直播间。
